# 기본 구현 완료 후 과제: 관리자 운영 도구

상태: **후속 과제로 승인됨 — 현재는 구현하지 않음**

BookEater의 기본 플레이·진화·원화·Windows 사용성 구현이 안정된 뒤, 개발자가 코드를
직접 다루지 않아도 변경 요청과 서비스 운영 현황을 관리할 수 있는 관리자 전용 도구를
구축한다.

## 1. 자연어 변경 요청 워크플로

개발자는 자연어로 기능 추가, 문구 수정, 버그 수정, 원화 교체와 배포 요청을 작성할 수
있다. AI 개발 도구가 저장소를 수정하되 변경을 운영 환경에 즉시 적용하지 않는다.

권장 흐름:

1. 자연어 요청 등록
2. 영향 범위·데이터 마이그레이션·위험 요약 생성
3. 별도 Git 브랜치와 변경안 생성
4. 자동 테스트 및 Windows 패키지/installer 회귀
5. 개발자 승인
6. 버전 증가, Release와 업데이트 채널 발행
7. 결과와 되돌리기 지점 기록

관리자 페이지가 임의의 코드를 직접 실행하거나 운영 Worker를 무검토 변경하는 기능은
만들지 않는다. 모든 변경은 Git 이력, CI 결과와 승인 기록을 남긴다.

## 2. 관리자 페이지 범위

### 운영 현황

- 현재 공개 버전과 업데이트 채널 상태
- 버전별 Release 일시, 설치파일 SHA-256과 배포 성공 여부
- GitHub Release 설치파일 다운로드 횟수
- 최신 변경 사항과 릴리스 노트 작성·검토 상태
- Cloudflare Worker 배포 버전, 상태 확인과 최근 오류 요약
- D1 사용량·보존기간 정리 작업 상태와 무료 요금제 한도 경고

다운로드 횟수는 GitHub Release 자산의 다운로드 수를 기준으로 한다. 이것은 실제 설치
인원·현재 활성 사용자 수와 같지 않음을 화면에 명시한다.

### 개선 데이터 관리

- 이용자가 **명시적으로 전송에 동의한** 개선 데이터 수와 처리 상태
- 이상 결과 신고, 모델 불확실 사례와 개발자용 명시적 교정 데이터 구분
- 개인정보 마스킹 결과와 보존 만료일
- 중복·오류 데이터 제외 및 데이터 내보내기
- 이용자 삭제 요청 처리와 처리 이력
- 모델/앱/동의문 버전별 집계

BookEater는 계속 local-first로 유지한다. 이용자의 책, 독서문장, 유전정보와 전체 로컬
SQLite DB는 기본적으로 전송하지 않는다. 관리자 페이지에서 볼 수 있는 것은 사전 고지와
동의를 거쳐 최소화·마스킹되어 업로드된 데이터뿐이다.

### 버전·변경 관리

- 다음 버전 번호 초안과 변경 목록
- 미완료 기능·알려진 오류·수동 검증 체크리스트
- CI 결과와 배포 가능 여부
- prerelease/정식 버전 발행 승인
- 이전 버전으로 되돌릴 때 사용할 Git 커밋과 배포 이력

### 대사·행동·진화 운영 설정

- 친밀도 구간별 대사 목록을 조회·추가·수정하고 미리보기
- 누적 독서 성향별 대사 목록과 적용 비중 확인
- 친밀도에 따른 말하기 빈도·활동성 변화 구간 조절
- 기록 누적에 따른 행동 변화와 진화 단계 조건 확인·조절
- 변경 전 유효성 검사, Windows 회귀 테스트, 버전 발행 승인
- 설정 변경 이력과 이전 값으로 되돌리기

대사나 진화 조건을 운영 중인 앱에 즉시 원격 주입하지 않는다. 관리자 페이지에서 만든
설정 변경안은 저장소의 검토 가능한 데이터 파일로 변환하고, 테스트와 승인을 통과한 서명된
앱 업데이트에 포함한다. 이용자별 독서 성향 원본은 관리자 페이지로 보내지 않는다.

## 3. 보안·권한 원칙

- 공개 앱과 분리된 관리자 인증 사용(Cloudflare Access 등)
- 관리자 API와 D1 원본 데이터는 일반 이용자에게 노출하지 않음
- 원본 데이터 조회·삭제·내보내기 권한을 분리하고 최소 권한 적용
- 중요한 작업은 재확인하고 누가 언제 무엇을 했는지 감사 로그 기록
- Cloudflare, GitHub, 알라딘 비밀키를 브라우저 코드나 저장소에 포함하지 않음
- 관리자 페이지에서 데이터베이스 임의 SQL 실행 기능은 제공하지 않음

## 4. 구현 시작 조건

다음 항목이 완료된 뒤 착수한다.

- 핵심 독서·진화·서재·돌보기 흐름의 Windows 수동 검증 완료
- 기본 및 진화 원화와 주요 애니메이션 확정
- 개선 데이터 동의문, 전송 전 미리보기, 철회·삭제 요청 흐름 구현
- 수집할 필드와 보존기간 확정
- 관리자 계정과 복구 방법 확정

## 5. 단계별 구현안

1. 읽기 전용 운영 대시보드: Release, 다운로드, Worker/업데이트 채널 상태
2. 동의 기반 개선 데이터 집계와 삭제 요청 처리
3. 릴리스 노트·버전·체크리스트 관리
4. 자연어 변경 요청을 Git 작업 항목으로 전환하는 보조 화면
5. 충분한 검증 후 승인 기반 빌드·배포 연결

초기 규모에서는 Cloudflare Pages/Workers/D1과 GitHub API를 조합해 무료 또는 매우 낮은
비용으로 시작할 수 있다. 실제 사용량이 늘면 D1 읽기·쓰기, 로그 보존과 GitHub API 한도를
대시보드에서 먼저 경고하도록 한다.
